更新时间：2026-09-22
项目仓库：`https://github.com/someone1128/ai-resume-node`

这份文档用于电脑维修、换机或长时间中断后恢复工作。恢复后先阅读本文件，再阅读根目录的 `AGENTS.md` 和 `CLAUDE.md`，最后根据剩余门禁继续开发。不要把本文件中的示例值当成真实凭证。

## 一、已经完成的工作

- 创建了独立 Node.js 后端仓库，和旧 Java/Snowy 仓库完全分离。
- 建立 TypeScript + Fastify + Kysely + MySQL2 + Redis 基础工程。
- 配置 `@/` 内部导入别名，构建时使用 `tsc-alias`。
- 保留现有前端 API 路径、Token 解析和响应包装。
- 完成简历核心、模板、收藏、发布、通知、分销、广告位、校园圈、字典和管理员兼容接口。
- 接入 DeepSeek/豆包兼容 AI、Vercel AI SDK、腾讯云 COS、微信 OAuth 兼容层和 mock 微信支付。
- 保留 AI 证件照和 AI 聊天；AI 聊天优先级较低，但接口和持久化基础已经建立。
- 完成线上只读调研和隔离测试账号回归，未修改数据库结构，未删除线上真实数据。
- 完成 40 个基础测试、类型检查、Lint、构建、生产依赖审计和健康检查基准工具。
- 完成两个用户端、后台管理端和浏览器扩展的既有迁移配套修改记录。
- 已将环境变量清单、阶段计划、接口盘点、数据库盘点、测试验收和切换方案写入 `docs/`。

## 二、电脑维修后你需要先完成的事项

这些事项需要你掌握账号、设备或线上权限，恢复后按顺序处理：

1. 确认 GitHub、腾讯云、微信开放平台/商户平台、DeepSeek 和火山引擎账号可以登录。
2. 轮换之前在协作中出现过的 DeepSeek、火山引擎 API Key；新的值只放在本地 `.env` 或部署平台环境变量中。
3. 准备一套本地或预发布环境变量。变量名从 `.env.example`、`docs/node-migration/environment-inventory.md` 和 Java YAML 读取，不要把真实值提交到 Git。
4. 确认 Node.js 22+、pnpm、Git、MySQL 客户端和 Redis 客户端已经安装。
5. 确认可以安全连接测试数据库和 Redis；如果只能连接线上库，继续遵守只读和测试前缀写入规则。
6. 提供或确认预发布微信 OAuth、微信支付证书/商户参数、管理员 SM2 登录配置和豆包图片模型配置。没有这些凭据时继续做 mock/fake 测试，不阻塞普通接口开发。
7. 确认最终部署位置、反向代理、域名和 Java/Node 灰度方式。切换方案必须支持快速回到 Java。
8. 在切换前确认数据库备份、恢复库和 COS 对象恢复流程。

## 三、恢复后第一批命令

在仓库根目录执行：

```bash
git status
git log -3 --oneline
pnpm install --frozen-lockfile
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm audit --prod --audit-level=high
```

如果 `format:check` 只报告历史迁移 Markdown 文档，先记录结果，不要为了清理格式一次性改动全部文档。README、AGENTS.md、CLAUDE.md 和本交接文档的改动应单独检查并提交。

## 四、后续开发顺序

### 1. 完成 Java/Node 全接口契约快照

- 从两个用户端、浏览器扩展和必要后台 API 清单中生成请求样本。
- 对同一测试账号和同一测试数据分别调用 Java、Node。
- 比较 URL、HTTP 方法、状态码、`code`、`data`、分页字段、错误结构和关键业务字段。
- 覆盖成功、未登录、无权限、数据不存在、参数错误和外部服务失败。
- 将差异写入 `docs/migration/`，每个差异明确“修 Node、改前端、保留旧行为”中的一种处理方式。

### 2. 补齐真实业务样本回归

- 使用脱敏 DOCX、PDF、TXT 和 JSON 简历样本。
- 对解析、创建、模块保存、AI 分析、AI 优化、报告读取和导出做字段快照。
- 验证中文、英文、空字段、超长文本、图片和异常文件。
- 不把真实用户简历复制到仓库或普通日志。

### 3. 预发布外部服务验收

- 微信 OAuth：真实 code exchange、用户资料同步、重复登录和失败回调。
- 管理员：真实 SM2 密码登录、Token TTL、退出和完整保留菜单。
- AI 证件照：豆包请求、返回图片签名校验、COS 上传、额度扣减、失败返还和记录状态。
- COS：私有对象上传、HEAD、签名下载、过期和删除。
- 微信支付：证书、签名、回调幂等、状态机、异常回放和重试；仍然禁止真实扣款测试。

### 4. 前端浏览器回归

- 用户端：登录后的 Token 注入、简历创建编辑、AI、会员、上传、校园圈、通知和发布。
- 证件照：模板、额度、上传、生成中、成功、失败和历史记录。
- AI 聊天：普通消息、流式消息、刷新、分页、重新回答和网络中断。
- 后台：登录、首页、字典分页、树、创建、修改、父子项删除保护和必要业务页面。
- 扩展：AI 网关、Token、结构化响应和错误提示。

### 5. 性能和运行保障

- 在相同机器、相同数据库和相近测试数据下分别运行 Java、Node。
- 记录冷启动、空闲 RSS、`/health` 延迟、核心接口 P95、AI 超时、上传吞吐、数据库连接数和 Redis 连接数。
- 使用 `pnpm bench:health` 做只读基准，禁止直接对生产用户压测。
- 验证 SIGTERM/SIGINT、连接释放、反向代理超时、SSE 超时和进程自动拉起。

### 6. 备份、灰度和回滚

- 生成 MySQL 备份并恢复到独立测试库。
- 验证恢复后的 Node 可以登录、读取简历和查询订单。
- 记录 Java 和 Node 的启动、停止、健康检查、日志和回滚命令。
- 先灰度少量请求，再扩大流量。
- 发生错误时切回 Java，并保留 Node 日志和接口差异记录。
- 只有灰度稳定、数据对照和回滚演练通过后，才讨论 Java 下线。

## 五、需要 AI/开发代理继续遵守的事项

- 不要把 Node 代码重新塞回 Java 仓库；本项目是独立 GitHub 仓库。
- 不要重新引入 Snowy 的完整权限、组织、岗位、代码生成和未使用模块。
- 不要修改数据库结构，除非先完成调研、写出迁移方案并得到明确决定。
- 不要删除线上真实数据；只允许清理本次创建且带测试前缀的测试对象。
- 不要为了本地测试调用真实微信支付或向生产用户发送通知。
- 不要把任何聊天中出现过的密钥写入 `.env.example`、测试文件、脚本、日志或提交历史。
- 所有内部导入使用 `@/`，新增依赖固定版本并同步锁文件。
- 每个阶段完成后更新 `docs/migration/progress.md`、测试记录和已知风险。
- 完成代码后运行受影响测试，再运行构建；提交前查看 `git diff`、`git status` 和敏感信息扫描。

## 六、阶段完成定义

一个阶段只有同时满足以下条件才算完成：

- 代码实现和接口清单完成；
- 环境变量和部署说明完成；
- 自动化测试通过；
- Java/Node 或前端实际流程完成对应回归；
- 测试数据、数据库写入和清理记录完整；
- 已知风险、监控方式和回滚方式明确；
- 进度文档已更新；
- Git 提交内容不包含密钥、证书、日志、构建产物和真实个人数据。
