# 阶段 8：精简后台

## 目标

保留业务管理能力，删除 Snowy 默认页面和复杂权限系统。

## 页面范围

首批迁移范围（本次必须完成）：

- 管理员登录；
- 首页；
- 字典管理。

后续按实际使用量决定是否迁移的页面：

- 用户、简历和模板；
- AI 优化记录和 AI 证件照记录；
- 会员套餐、订单、支付记录和兑换码；
- 校园市场圈；
- 通知、反馈和广告位。

候选删除：

- 角色、资源、模块、菜单、按钮、字段；
- 组织、岗位；
- 移动端资源；
- 代码生成；
- 系统监控；
- Snowy 开发配置中心；
- 未实际使用的短信、邮件和多云文件配置页面。

## 处理方式

先保留现有 Vue 页面作为迁移参考和过渡界面。首批只实现首页和字典，避免为了 Snowy 默认页面扩大迁移范围：

1. 根据调研结果隐藏无用菜单；
2. 管理员登录改为 Node 接口；
3. 字典改为 Node 的简单字典接口；
4. 首批页面和 API 稳定后，再按真实使用记录决定是否重建其它页面。

当前状态：Snowy Vue 管理端依赖已安装并完成 Vite 生产构建；构建前补齐了首页流量分析页面缺失的 `src/api/app/gaApi.js` 客户端文件。Node 目前只暴露首页和字典管理两个精简菜单，字典保留 `/dev/dict/*` 与 `/biz/dict/*` 两组兼容路径，并已完成线上测试 Token 下的分页、树查询、增删改和父项删除保护。用户确认后台重要程度较低，因此用户端迁移完成前不复制 Snowy 全部页面；其它页面保留为有真实需求时再开启的后续阶段，管理员真实密码登录和完整后台浏览器回归留给预发布。

## 测试实例

- 首页和字典页面可打开；
- 字典分页、树查询、搜索和表单可用；
- 管理员登录和退出；
- 管理员可以访问首批迁移页面；
- 不再显示 Snowy 默认菜单；
- 字典修改能影响真实业务；
- 上传页面只显示腾讯云 COS 流程；
- 浏览器刷新后 Token 和菜单状态正确。

## 当前验收结果

精简管理员菜单不再显示 Snowy 角色、组织和开发工具模块，数据库中现有管理员统一拥有已迁移页面的完整权限。字典管理已可独立完成日常维护；其它后台页面是否重建以实际使用清单为准，不阻塞用户端 Node 迁移。
