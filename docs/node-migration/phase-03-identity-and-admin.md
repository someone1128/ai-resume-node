# 阶段 3：微信登录、管理员和字典

## 目标

先建立所有后续业务都依赖的身份和基础管理能力。

## 用户登录

- 兼容现有微信登录入口和回调；
- 保持前端已有 Token 传递方式；
- 用户首次登录的创建和重复登录幂等；
- 旧用户 ID、微信标识和资料字段保持兼容；
- 退出和 Token 失效行为兼容现有前端。

## 本地登录后接口测试

本地无法完成微信 OAuth 时，不阻塞其他接口测试。提供一个仅限 `development`/`test` 环境的测试身份机制：

- 测试用户 ID 通过环境变量指定；
- 测试 Token 通过环境变量指定或由本地脚本生成；
- 请求通过现有 `token` 请求头发送；
- 可直接测试简历、AI、会员、COS 和校园市场圈接口；
- 测试用户数据使用独立账号或明确的测试数据；
- Token 不提交到 Git、不写入日志、不放进 `.env.example`；
- production 环境发现测试 Token 配置时直接拒绝启动。

如果需要复用已经获得的登录 Token，只允许临时通过本机环境变量或命令行注入，不将真实用户 Token 固化到代码、文档、截图或自动化测试产物中。

## 管理员

管理员模型保持简单：数据库中已有几个管理员就迁移几个，每个管理员拥有全部保留后台权限。

不迁移：

- 角色资源树；
- 按钮/字段权限；
- 组织和岗位授权；
- 移动端资源权限。

## 字典

保留真实业务读取的字典能力，但不复制 Snowy 的完整开发配置中心。先根据阶段 0 的清单确定：

- 字典分类；
- 字典项；
- 排序；
- 启用状态；
- 前端实际使用的值和标签。

## 测试实例

- 微信登录成功；
- 微信登录回调重复访问；
- 登录失败和用户取消授权；
- 不经过微信回调，使用本地测试 Token 调用已登录接口；
- 测试 Token 只能在本地/测试环境生效；
- production 拒绝测试 Token；

当前实现已提供管理员兼容层：现有 Snowy B 端 Token 可以通过 Redis `token:B:token:<token>` 继续访问，Node 管理员登录在配置 `ADMIN_LOGIN_ENABLED=true` 和外部注入 `ADMIN_SM2_PRIVATE_KEY` 后会校验 `sys_user` 的账号与 SM3 密码摘要，生成带 TTL 的 Node 会话；菜单只返回已迁移的业务页面并统一视为完整权限。真实微信 OAuth 和真实管理员密码登录不在本地执行，留到预发布环境验证；本地和线上只读回归使用测试 Token。
- 已有用户再次登录不重复创建；
- Token 过期后用户端得到兼容的 401；
- 管理员登录后可访问所有保留后台接口；
- 普通用户不能访问后台接口；
- 字典查询、添加、修改、禁用和排序；
- 删除正在被业务使用的字典项时得到明确错误。

## 当前验收结果

Node 已通过测试 Token 的用户接口和管理员菜单保护测试；字典 `/dev/dict/*` 与 `/biz/dict/*` 兼容别名已完成分页、树查询、增删改和父项删除保护的线上测试。用户首次登录、重复登录和真实微信回调仍需预发布凭据验证。用户和管理员身份可独立运行，后续模块不再依赖 Snowy 细粒度权限表。
