# 阶段 6：会员、权益、兑换码和微信支付

## 目标

迁移会影响真实资金和权益的功能，优先保证幂等、准确和可回滚。

## 工作项

- 会员套餐查询；
- 用户权益查询；
- AI/功能次数查询；
- 兑换码校验和使用；
- 微信支付订单创建；
- 微信支付回调；
- 订单查询；
- 充值/购买记录；
- 退款或异常订单处理（若现有业务使用）。

## 关键规则

- 金额使用整数分或 Decimal，禁止浮点数；
- 微信回调验签；
- 回调按订单号幂等；
- 订单状态只能按允许的状态机流转；
- 会员权益只能发放一次；
- 兑换码只能成功使用一次；
- 支付成功和权益发放必须可追踪。

当前状态：会员套餐、功能次数、兑换码查询、mock 订单、回调幂等和权益发放已迁移。`PAYMENT_MODE=live` 目前明确拒绝创建和回调，直到补齐微信支付验签、金额校验、证书配置和预发布回放；不会在未验签的情况下确认支付或发放权益。

## 测试实例

- 创建订单成功；
- 重复创建同一业务订单；
- 支付回调成功；
- 同一回调重复发送；
- 签名错误；
- 订单不存在；
- 金额不一致；
- 回调中途数据库失败后重试；
- 权益已发放后再次回调；
- 兑换码重复使用；
- 会员过期和未生效；
- 订单查询和后台展示一致。

## 当前验收结果

Node 可以在 mock 模式独立处理测试订单和权益发放，重复回调不会重复发货或扣费；live 模式会 fail-closed，待预发布完成验签、金额一致性、异常重试和真实订单查询后再打开。
