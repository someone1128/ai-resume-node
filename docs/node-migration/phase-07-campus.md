# 阶段 7：校园市场圈

## 目标

在用户、管理员、COS 和基础认证稳定后迁移校园市场圈。

## 工作项

- 校园市场圈用户和认证；
- 内容和岗位信息；
- 招聘记录；
- 进度和统计；
- 图片上传；
- 管理员内容维护；
- 邀请、投递记录和状态维护；
- 现有安全 Cookie、CSRF 和来源校验。

## 关键规则

- 所有图片只写腾讯云 COS；
- 上传大小、格式和用户归属校验；
- 用户状态和投递记录按用户 ID 隔离，取消投递时保持 Java 的删除语义；
- 当前前端接口清单没有独立的“每日解锁额度”或“解锁”接口，因此不新增未被实际使用的限制模型；
- 管理端和用户端数据隔离；
- 保留现有域名和 Cookie 行为，迁移期间不随意改变前端协议。

## 测试实例

- 用户登录后查看内容；
- 未登录访问公开内容；
- 登录和未登录查看校招/内推列表；
- 按招聘状态筛选，状态与用户招聘记录保持一致；
- 重复投递、取消投递和投递记录归属校验；
- 自定义记录新增、修改、删除及系统记录不可冒充自定义记录；
- 图片上传和删除；
- 非本人图片访问；
- 管理员新增、修改、下线内容；
- 非法来源和 CSRF 请求；
- COS 上传失败后的数据回滚。

## 通过条件

校园市场圈在 Node 上完整运行，列表、状态、投递记录、统计和管理端内容维护与现有线上行为一致；不存在于实际前端接口清单的解锁限制不作为迁移门禁。

## 当前验收结果

Node 已对齐 Java 的 `listCampusRecruitment2` 和 `listUserRecruitmentRecords` 关键查询：登录用户状态筛选、用户备注搜索、进度空值过滤、系统记录“取消/空状态”过滤和自定义记录归属均保留。使用线上数据库的只读接口验收中，校招、内推、进度和投递记录接口均返回成功；线上专用测试账号已完成自定义记录新增、分页读取、修改、删除和重复删除错误回归。系统岗位投递/取消投递仍需在预发布选取没有既有关系的岗位样本。
