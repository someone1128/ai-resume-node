# 阶段 5：AI 简历、AI 证件照和 AI 聊天

## 优先级

1. AI 简历分析和优化；
2. AI 证件照；
3. AI 聊天。

AI 聊天保留，但不阻塞前两项和用户核心流程。

## AI 简历

- DeepSeek 负责文本分析和优化；
- 测试阶段统一使用 DeepSeek Flash 模型，Key 只通过运行时环境变量注入；
- 豆包按当前业务实际用途实现文本或图像能力；
- 所有模型调用通过 AI service；
- 设置超时、重试上限、最大输入长度和输出长度；
- 记录 provider、model、耗时、成功/失败和消耗；
- 会员次数扣减必须与业务结果保持一致；
- 失败请求不能错误扣费。

## AI 证件照

- 使用豆包/火山引擎图片能力；
- 输入和输出图片统一走腾讯云 COS；
- 不保留多存储引擎分支；
- 生成记录、失败记录和图片 URL 可追踪；
- 对文件大小、格式和用户归属做校验。

当前实现已完成输入图片上传到 COS、生成结果为 base64 或远程 URL 时回存 COS、生成记录和失败回滚路径；远程图片下载使用统一超时客户端。豆包/火山引擎真实生成仍需预发布凭据和样本验证。

## AI 聊天

使用 Vercel AI SDK 的 `generateText`/`streamText`，并根据当前 SDK 文档验证 API。聊天接口需要明确：

- 是否持久化对话；
- 是否限制上下文长度；
- 是否扣减会员次数；
- 客户端使用哪种流协议；
- 断开连接后的取消和计费行为。

## 测试实例

- DeepSeek 成功响应；
- 豆包成功响应；
- 外部超时；
- 外部 4xx/5xx；
- 空响应和非法结构；
- 超过输入长度；
- 重试后仍失败；
- 成功只扣一次权益；
- 失败不扣权益；
- 重复请求幂等；
- AI 证件照上传、生成、下载和删除；
- 流式聊天中途断开；
- 流式输出错误不会泄漏密钥和内部异常。

## 当前验收结果

DeepSeek 文本测试、AI 简历分析/优化、额度失败返还、AI 聊天会话持久化和流式入口已完成 Node 回归；TXT/MD/JSON/HTML 文件解析和不支持格式拒绝已完成，证件照上传（`/c/photo/file/upload`）、COS 输入/输出链路和失败记录已完成实现。火山方舟 provider 已完成一次真实图片生成调用，脱敏 DOCX/PDF 样本、证件照完整数据库/COS 链路和生产外部网络断开场景留给预发布专项验收。AI 业务可以在没有 Java AI 服务的情况下运行，并具备失败、计费和审计边界。
