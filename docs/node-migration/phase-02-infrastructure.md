# 阶段 2：基础设施和兼容层

## 目标

实现业务模块共用的数据库、Redis、Token、COS、配置和外部请求能力。

## 当前实现状态（2026-09-21）

已完成：Kysely + mysql2 连接封装、核心简历表类型、只读线上盘点脚本、Snowy 客户端 Token/Redis 会话兼容、测试身份 Token 适配、环境变量校验、CORS 白名单、统一外部 HTTP 超时封装和腾讯云 COS 封装。已用线上配置验证 Redis PING/读写/TTL/删除，以及 COS 上传、HEAD、签名 URL、删除和删除后不存在；线上 Node API 也已验证真实简历数据查询。

本阶段只剩专项外部环境验证：微信 OAuth、微信支付签名/回调和生产发布前的故障演练。真实支付不会在迁移测试中扣款。

## 工作项

### 配置

以 [environment-inventory.md](environment-inventory.md) 为来源，使用 Zod 校验环境变量。只保留实际需要的配置：

- MySQL；
- Redis；
- 微信登录；
- 微信支付；
- 腾讯云 COS；
- DeepSeek；
- 豆包；
- 应用 URL 和 Cookie。

从现有 YAML 和数据库配置表迁移键名和环境差异，但不复制明文密钥。生成 `.env.example` 和按环境的部署变量清单。数据库配置只读核对；不通过迁移程序修改配置表。

不建立 Snowy 风格的后台配置中心。密钥只从环境变量读取。

### 数据库

- 连接现有 MySQL；
- 先建立只读查询和事务封装；
- 只为确认保留的表建立类型；
- 不删除旧表；
- 不在本阶段修改核心表结构。

### Redis

仅用于确认过的会话、缓存、限流和任务状态。每个 Key 必须记录 TTL、数据结构和清理方式。

### Token

保持外部 Token 请求方式兼容。内部可以重新实现会话，但必须先完成旧 Token 的兼容策略和失效策略。

### COS

只实现腾讯云 COS：

```text
upload
delete
createDownloadUrl
exists
```

不实现阿里云、MinIO、本地文件和动态存储引擎选择。

### AI 基础接口

本阶段只定义接口，不实现具体业务：

```ts
generateText()
streamText()
generateStructuredOutput()
generateImage()
```

DeepSeek 和豆包的 provider 适配在 AI 阶段实现。

## 测试实例

- 缺少必需环境变量时启动失败并指出变量名；
- local/test/prod 的必需变量集合正确；
- production 不能启用测试 Token；
- `.env.example` 不含密钥；
- 数据库连接失败时应用给出可读错误；
- 数据库事务提交、回滚有效；
- Redis 读写、TTL 和断线重连有效；
- Token 读取、失效和过期有效；
- COS 上传、下载 URL、删除和重复上传有效；
- 上传失败不会在数据库留下无效 URL；
- 外部 HTTP 请求有超时、取消和错误分类；
- 所有日志隐藏密钥、Token 和用户内容。

## 数据库访问边界

- 调研阶段优先使用只读连接；
- 允许为测试创建带唯一前缀的测试用户和关联测试数据；
- 允许为测试用户赋予测试会员权益；
- 禁止 DDL、删表、改表结构、删除线上真实数据和批量修改真实用户；
- 所有测试写入必须记录主键、用途和清理方式；
- 测试数据不能与真实用户、真实订单和真实支付回调混用。

## 通过条件

基础设施已经可以被业务模块复用；业务模块通过数据库、Redis、COS 和 HTTP 统一封装访问基础设施，不直接散落 SDK 调用。进入生产切换前仍要完成预发布外部回调和回滚演练。
