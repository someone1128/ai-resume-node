# 阶段 4：简历核心业务

## 目标

完成用户端最核心的简历闭环，并尽量保持现有 API 协议。

## 迁移范围

- 创建和初始化简历；
- 我的简历列表；
- 简历详情；
- 简历更新和删除；
- 简历模块更新；
- 简历名称、封面、模板和样式；
- 发布、取消发布、收藏；
- 模板列表和分类；
- 简历使用记录；
- 简历导出依赖的文件能力。

## 实现原则

- 所有查询按用户 ID 隔离；
- 更新接口只允许修改本人数据；
- 保持现有字段名称和分页结构；
- 先兼容旧表，不先重构 JSON 字段；
- 对创建、更新、删除和发布操作增加结构化审计日志；日志只记录 requestId、路由模板、方法、操作者和状态，不记录简历正文、Token 或请求体；
- 简历模块更新需要校验模块归属关系。

## 测试实例

- 新用户创建第一份简历；
- 同一用户创建多份简历；
- 列表分页和空列表；
- 查询不存在的简历；
- 用户 A 不能读取或修改用户 B 的简历；
- 更新单个模块不覆盖其他模块；
- 并发保存同一份简历；
- 删除、取消发布和收藏幂等；
- 模板不存在或已禁用；
- 大型简历 JSON 保存和读取；
- 现有前端页面完整回归。

## 当前验收结果

线上测试账号已经完成创建、详情、基础信息、名称、模板、预览图、样式、模块、收藏、使用、发布、取消发布和软删除全链路回归；测试简历和公开副本均已清理为不可见状态。剩余工作是对仍被页面使用的分析报告字段做 Java/Node 快照，而不是简历核心写流程缺失。

Node 已完成创建、编辑、保存、预览、发布、取消发布、收藏、使用和删除路径；写操作使用事务边界并通过结构化 mutation audit 记录。线上测试夹具已验证本人访问和跨用户未公开简历隔离；模板分页已经完成 Java/Node 只读契约烟测并修正为 Java `CommonPage` 字段。完整简历字段快照和并发保存压力测试仍属于切换前门禁。
