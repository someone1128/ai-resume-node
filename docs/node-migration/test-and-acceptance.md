### 1. 静态检查

每次提交都必须执行：

```text
typecheck
lint
format check
dependency audit
```

禁止提交：

- 编译错误；
- 未使用的依赖；
- `.env`、Token、密钥和证书；
- 调试接口；
- 生产配置中的测试开关。

### 2. 单元测试

用于验证不依赖网络和真实数据库的业务规则：

- 参数转换；
- 权益计算；
- 次数扣减；
- 订单状态机；

- Token 解析；
- AI 请求参数构建；
- 分页和排序。

外部服务通过 fake 或 mock 注入，不在单元测试中调用真实微信、AI 或 COS。

### 3. API 集成测试

使用测试数据库和测试 Redis，验证：

- 路由和参数校验；
- 数据库读写；
- 事务提交与回滚；
- Token 认证；
- 用户数据隔离；
- 管理员访问；
- 文件上传；

本地可以通过 `TEST_USER_ID` 和 `TEST_AUTH_TOKEN` 测试登录后接口，微信 OAuth 不作为普通接口测试的前置条件。

### 4. Java/Node 契约对照测试

在 Java 仍可运行期间，对同一测试数据分别调用 Java 和 Node：

- 请求路径相同；
- 请求参数相同；
- HTTP 状态码一致；
- `code`、`data`、`msg`/`message` 结构兼容；
- 分页字段兼容；
- 业务结果等价；
- 错误场景等价。

不要求 JSON 字段顺序或内部实现一致，但要求前端可无修改消费 Node 响应。

契约对照必须覆盖成功、未登录、无权限、数据不存在、参数错误和外部服务失败。

## 回滚规则

任何一个条件出现，都暂停切换并回滚对应流量：

- 支付状态或权益不一致；
- 用户简历读取或保存异常；
- 文件出现不可访问或越权；
- Token 大面积失效；
- AI 扣费与结果不一致；
- 错误率明显高于 Java 基线；
- 核心数据计数不一致且无法解释。

回滚只切换流量和配置，不立即删除 Node 数据或 Java 数据，待问题定位后再决定是否修复或重做。
